# Sotto v0.1: design spec

- **Status:** draft for review
- **Date:** 2026-10-12
- **License:** MIT

Sotto is an open-source, local-only noise-cancelling virtual microphone for macOS. It is a free alternative to Krisp's core feature: removing background noise from your mic in any call app.

**Background:**
- [Krisp architecture research](../../krisp-architecture.md) (clean-room notes)
- [Benchmark](../../../bench/README.md): DeepFilterNet3 matches Krisp's standard noise removal on our synthetic set (DNSMOS OVRL 3.09 vs 3.07) at about 4% of one CPU core.

---

## 1. Goals and non-goals

### Goals (v0.1, the "fast" release)
1. Any call app (Zoom, Google Meet in Chrome, Teams) can pick **"Sotto Microphone"** and receive the user's mic with background noise removed.
2. A menu-bar app provides: on/off, strength, hold-to-compare (A/B), physical-mic picker, and status.
3. **End-to-end added latency of 60 ms or less** and **under 10% of one CPU core** on an Apple Silicon MacBook Air.
4. Fail-safe behaviour: overload, model errors and device loss never leave the call without audio while the app is running.
5. A **source release**: anyone can build and install with one command, with no Apple Developer account required.
6. 100% local: no network, accounts or telemetry.

### Non-goals (deferred)
| Deferred | Target |
|---|---|
| Automatic default-device switching | v0.2 |
| Per-app call detection, debounce, ignore lists | v0.2 |
| Raw passthrough when the app is not running | v0.2 |
| Advanced Bluetooth handling (new-device grace period, profile switching) | v0.2 |
| Signed and notarized `.pkg`, Homebrew cask | When there is demand (needs an Apple Developer ID) |
| Speaker (incoming audio) cleaning, voice isolation (background voices), echo cancellation | v0.3+ |
| 44.1 kHz driver rate, Windows and Linux | Later |

## 2. Architecture

```
┌─────────────────────────── Sotto.app (menu bar, Swift/SwiftUI) ─────────────────────────┐
│ UI ─ on/off · strength · hold-to-compare · mic picker · status                          │
│ DeviceMonitor ─ physical input list, default input, selected-mic loss, coreaudiod restart│
│ AudioEngine ─ capture IOProc → ring A → DSP thread → ring B → bridge IOProc             │
│   └─ Denoiser (Rust staticlib, C ABI) ─ DeepFilterNet3 via the `deep_filter` crate (tract)│
│ Watchdog ─ per-frame timing (overload), no-frames, all-zeros                            │
│ Settings ─ UserDefaults (mic UID, strength, enabled, launch at login)                   │
└──────────────────────────────────────┬──────────────────────────────────────────────────┘
                                       │ Core Audio (ordinary client)
┌──────────────────────────────────────▼─────────── SottoAudio.driver (HAL plug-in, C++) ─┐
│ "Sotto Microphone" (visible input)    ◄── lock-free ring ──   "Sotto Bridge" (hidden output)│
│ custom properties: running · bridgeConnected · hidden                                    │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

| Unit | Language | Responsibility | Depends on |
|---|---|---|---|
| `driver/` | C++ (fork of BlackHole, MIT) | Presents the two devices and moves audio from the bridge to the mic | Core Audio HAL |
| `denoiser/` | Rust crate → staticlib + C header | `process(frame)` with DeepFilterNet3. No audio-device code | `deep_filter` crate |
| `app/` | Swift, SwiftUI, a small C shim for real-time code | Capture, DSP thread, rings, UI, device monitoring, watchdog | driver (at runtime), denoiser (linked) |
| `bench/` | Python (exists) | Quality regression and live latency measurement | — |

**Identifiers:**
- GitHub org `sotto-audio`, repo `sotto`.
- Bundle IDs `io.github.sotto-audio.Sotto` (app) and `io.github.sotto-audio.SottoAudio` (driver).
- Device UIDs `SottoMicrophone` and `SottoBridge`.

## 3. Audio flow and timing

```
Physical mic (any rate/channels)
  → Capture IOProc: downmix to mono, resample to 48 kHz if needed, write ring A
  → DSP thread: read 480 samples (10 ms) → Denoiser.process → strength/bypass mix → write ring B
  → Bridge IOProc (output on "Sotto Bridge"): read ring B (with drift correction) → driver
  → driver ring (1-frame target delay) → "Sotto Microphone" → call app
```

**Format:** 48 kHz, mono, float32 internally. DeepFilterNet3 runs natively at 48 kHz with a 480-sample hop, so the model needs no resampling.

**Resampling:** only at capture, and only when the physical device is not at 48 kHz. Uses the libsamplerate algorithm `SRC_SINC_FASTEST` (BSD-2, vendored), with per-stream state.

**Threads:**
- **Capture and bridge IOProcs** (Core Audio real-time threads) only copy, downmix or resample, and move ring indices. They take no locks, allocate no memory, do no logging and make no calls into Swift.
- **DSP thread:**
  - one pthread with the time-constraint policy (period 10 ms, computation 5 ms, constraint 10 ms);
  - joined to the capture device's `kAudioDevicePropertyIOThreadOSWorkgroup`;
  - waits on a semaphore that capture signals once ring A holds ≥ 480 samples.

**Rings:** single-producer/single-consumer, lock-free, power-of-two capacity, atomic head and tail (acquire/release). Ring A holds 8 frames; ring B holds 8 frames with a **target fill of 1 frame**.

**Drift correction (ring B):**
- Fill is tracked as an exponential moving average (time constant about 1 s).
- When the average is more than ±0.5 frame from target, the DSP thread drops or duplicates **one sample per frame**, chosen at the lowest-energy point, until fill is back within ±0.25 frame.
- On a hard underrun, the bridge outputs the last 10 ms faded to zero and re-primes to target.

**Latency budget:**

| Source | Estimate |
|---|---|
| Capture IO buffer | 10 ms |
| DeepFilterNet3 algorithmic latency (STFT plus lookahead) | about 30–40 ms; measured in the prototype |
| Ring B target | 10 ms |
| Driver delay | 10 ms (reported via `kAudioDevicePropertyLatency`) |
| **Target** | **≤ 60 ms** |

**Strength mapping:**
- `strength` 0–100 sets DeepFilterNet's attenuation limit: `atten_lim_db = strength × 0.4` (0–40 dB). At 100, the limit is removed (100 dB).
- `strength = 0` or "off" is a bypass: original audio follows the same path with the same latency, so toggling never glitches or shifts timing.
- Bypass and hold-to-compare crossfade over 10 ms.

**Engine lifecycle:**
- The engine runs only while `running` (driver property) is true, i.e. some app is reading Sotto Microphone, **and** the user has Sotto enabled. Otherwise capture is stopped, which saves CPU and turns off the mic-in-use indicator.
- On a change of the selected mic, its sample rate, or after a coreaudiod restart, the engine is **rebuilt** (stopped, then started with new formats) rather than reconfigured in place.

## 4. Driver (`SottoAudio.driver`)

Forked from BlackHole and restructured into two devices on one plug-in.

| Object | Details |
|---|---|
| **Sotto Microphone** | Input, 1 ch, 48 kHz float32. Can be the default device. Has volume and mute controls. |
| **Sotto Bridge** | Output, 1 ch, 48 kHz float32. Hidden (`kAudioDevicePropertyIsHidden = 1`). Cannot be the default device. IO only for the authorised client. |

**Custom properties** (CFNumber, global scope):

| Selector | Name | Access | Meaning |
|---|---|---|---|
| `'sRun'` | running | read, notifies | 1 while any client other than Sotto.app is doing input IO on Sotto Microphone |
| `'sBrg'` | bridgeConnected | read, notifies | 1 while an authorised client is doing output IO on Sotto Bridge |
| `'sHid'` | hidden | read/write | Sotto.app hides the microphone on quit and shows it on launch |

**Authorisation:**
- At `AddDeviceClient`, the driver obtains the client's code-signing **team identifier** (via `SecCode` from the client audit token, or the PID where the audit token is unavailable).
- It compares that against `SOTTO_TEAM_ID`, which is baked in at build time from the build's own signing identity.
- For unsigned or ad-hoc local builds, `SOTTO_TEAM_ID` is empty and the check falls back to an exact bundle-ID match on `io.github.sotto-audio.Sotto`. The build script logs which mode was compiled.
- Clients that are not authorised get no IO on the bridge.

**Audio path:**
- **Shared clock:** both devices share one clock anchor (`mach_absolute_time` at plug-in init, 48 kHz host-tick scaling) and the same zero-timestamp period, so their sample timelines are phase-locked.
- **Bridge write:** stores frames at `outputTime.mSampleTime` in a lock-free, sample-time-indexed ring (capacity 8,192 frames).
- **Mic read:** fetches at `inputTime.mSampleTime − 480`, a fixed 1-frame delay that is reported as latency.
- **Missing data** (bridge not connected, or underrun) is read as silence.
- Volume and mute are applied with the correct channel count. Gain changes are ramped over the buffer.

**Real-time rules:**
- No locks, logging, allocation or Objective-C/CF calls on the IO path.
- The client list used on the IO path is a fixed-size atomic array.
- Property notifications are posted from a non-real-time queue.

**Install:**
- `make install` copies the driver to `/Library/Audio/Plug-Ins/HAL/` (needs sudo) and runs `killall coreaudiod`.
- `make uninstall` reverses both steps.

## 5. Denoiser library (`denoiser/`)

C ABI (`sotto_denoiser.h`):
```c
typedef struct SottoDenoiser SottoDenoiser;
SottoDenoiser *sotto_denoiser_new(void);                 // loads embedded DFN3 model; NULL on failure
uint32_t       sotto_denoiser_hop_size(const SottoDenoiser *);   // 480
uint32_t       sotto_denoiser_latency_samples(const SottoDenoiser *);
void           sotto_denoiser_set_atten_lim_db(SottoDenoiser *, float db);
int32_t        sotto_denoiser_process(SottoDenoiser *, const float *in, float *out); // one hop; 0 = ok
void           sotto_denoiser_reset(SottoDenoiser *);
void           sotto_denoiser_free(SottoDenoiser *);
```

- **Model:** the DeepFilterNet3 default model, embedded via the `deep_filter` crate's default-model feature (MIT/Apache-2.0).
- **Allocation:** `process` does not allocate after the first call. It is called only from the DSP thread.
- **Panic safety:** every entry point catches panics and returns an error code; it never unwinds across the FFI boundary.
- **Fail-open:** a non-zero return makes the engine output the input frame (passthrough) and increment an error counter.

## 6. App (`Sotto.app`)

**Menu-bar popup (SwiftUI `MenuBarExtra`, macOS 14+):**
- **Enable toggle.**
- **Microphone picker:** physical inputs only. Excludes Sotto devices, the hidden bridge and aggregates. "System default" is the default choice.
- **Strength slider:** 0–100, default 80.
- **"Hold to hear original"** button.
- **Status line:**
  - Idle, or Active, with the client app name if available from the driver (best effort);
  - CPU % of the DSP thread;
  - estimated latency.
- **Warnings:**
  - "Driver not installed / version mismatch";
  - "Microphone permission needed";
  - "Using original audio (overloaded)";
  - "Selected mic disconnected, using <fallback>".
- **Footer:** Setup help, Settings (launch at login), Quit.

**First run:**
1. If the driver is missing, show the build/install command and a link to the README. The app does not install drivers itself in v0.1.
2. Request microphone permission.
3. A one-screen guide: "Select **Sotto Microphone** in your call app."

**DeviceMonitor:**
- Listens to `kAudioHardwarePropertyDevices`, `kAudioHardwarePropertyDefaultInputDevice` and `kAudioHardwarePropertyServiceRestarted`, plus `kAudioDevicePropertyNominalSampleRate` and `kAudioDevicePropertyDeviceIsAlive` on the active mic.
- If the selected mic disappears, it falls back to the system default (then the built-in mic) and rebuilds the engine.
- After a coreaudiod restart, it re-resolves all devices and rebuilds.

**Watchdog:**

| Check | Rule | Action |
|---|---|---|
| Overload | DSP time per frame, moving average over 50 frames. Soft threshold 3.75 ms (37.5%), hard threshold 7.5 ms (75%) | Soft: show a warning. Hard, sustained for 20 frames: crossfade to bypass, then retry processing after 30 s |
| No frames | No capture callback for 3 s while running | Warning, and rebuild the engine once |
| All zeros | Captured energy ≤ 1e-8 for 5 s | Warning ("Mic may be muted or blocked") |
| Denoiser errors | More than 10 consecutive errors | Bypass, warning, then reset the denoiser after 5 s |

**Settings:** stored in UserDefaults: `selectedMicUID`, `strength`, `enabled`, `launchAtLogin` (via `SMAppService`).

**Privacy:** the app has no network entitlement and no analytics. Logs (os_log) contain no audio data and no device serials.

## 7. Error handling summary

| Failure | Behaviour visible to the call app |
|---|---|
| Model fails to load | Sotto runs in bypass. The app shows an error |
| DSP overload | Brief crossfade to original audio; the call continues |
| Selected mic unplugged | Short silence (under 0.5 s), then audio continues from the fallback mic |
| Sotto.app quits normally | Microphone is hidden; apps fall back to another mic |
| Sotto.app crashes | Microphone stays visible but outputs silence (`sBrg = 0`). Relaunch restores audio |
| coreaudiod restart | Driver reloads; the app rebuilds within about 2 s |

## 8. Testing

| Level | Test | Pass criteria |
|---|---|---|
| Denoiser | Rust unit tests (hop size, reset, attenuation mapping, error codes, no panics across FFI) | All pass |
| Denoiser quality | `bench/`: process the 192-clip set through the library | **DNSMOS OVRL ≥ 3.0, SI-SDR ≥ 15 dB** (baseline 3.09 / 16.2) |
| Rings and drift | Unit plus stress tests: producer and consumer at ±0.1% rate offset, 2 simulated hours | No underruns after settling; fill within ±0.5 frame |
| Driver | Loopback test tool: write a known signal into Sotto Bridge, read Sotto Microphone | Bit-exact samples; delay exactly 480 samples; no gaps in 10 minutes |
| End to end | `bench/` live harness: BlackHole as the "physical mic" → Sotto → record Sotto Microphone | Latency **≤ 60 ms**; scores within 0.1 DNSMOS of offline; CPU **< 10%** of one core |
| Manual (release blocker) | Zoom, Meet (Chrome), Teams × built-in mic, Jabra USB, AirPods (switch mid-call) × sleep/wake, coreaudiod restart, app quit and crash × macOS 14, 15 | Checklist all green |

**CI (GitHub Actions, macOS):**
- Builds the driver, denoiser and app.
- Runs the Rust and Swift unit tests, the ring stress test (shortened) and the denoiser quality regression.
- Driver install and live tests run locally only.

## 11. Open questions (resolved during M1–M3)
- DeepFilterNet3's actual lookahead latency with the `deep_filter` crate defaults. If above 40 ms, evaluate reduced-lookahead settings or DPDFNet (used by the Linux project HushMic) as alternatives.
- Whether the `deep_filter` crate's tract backend meets the < 10% CPU target inside the real-time thread. The benchmark measured a real-time factor of 0.043 with the CLI.
- Whether the client audit token is available to HAL plug-ins in `AddDeviceClient` on macOS 14 and 15 (otherwise use the PID-based `SecCode` lookup).
